# Правила командной работы

## Учебные команды

| Команда | Зона ответственности | Примеры задач |
| --- | --- | --- |
| Core | правила задач, API, хранение | валидация, JSON, обработка статусов |
| Web | интерфейс и удобство | форма, доска, адаптивная верстка |
| QA | проверки и демонстрация | тест-кейсы, регрессия, сценарий защиты |

Названия команд показывают распределение ролей в учебном плане. Это роли для примера, а не реальные участники GitFlic-проекта.

## Канбан-процесс

1. Задача начинается в **Бэклоге**.
2. Команда берёт её в **Работу** и уточняет критерии готовности.
3. После проверки задача переходит в **Готово**.
4. Если проверка нашла проблему, задача возвращается в **Работу**.

## Минимальный шаблон задачи

```markdown
### Зачем
Коротко описать проблему.

### Готово, когда
- [ ] результат виден в приложении;
- [ ] тесты подтверждают ожидаемое поведение;
- [ ] инструкция обновлена, если это нужно.
```

## Договорённости

- одна задача описывает один проверяемый результат;
- зависимости отмечаются между связанными задачами;
- токены и пароли нельзя хранить в репозитории;
- перед завершением блока команда показывает работающий результат.
