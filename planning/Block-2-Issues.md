# Блок 2 — карточки задач

Учебная доска проекта «Дедлайнатор». Команды Core, Web и QA — распределение работ для планирования, а не реальные учётные записи участников.

Предлагаемые метки GitFlic: team::Core, team::Web, team::QA, type::feature, type::test, type::docs.

## I01. Уточнить сценарии и критерии готовности

**Команда:** Core + QA  
**Результат:** согласованы сценарии создания задачи, срока, приоритета и смены статуса; подготовлены примеры входных данных.  
**Готово, когда:** критерии приёмки записаны и используются в задачах I02, I05 и I07.  
**Спринт:** 1

## I02. Реализовать модель задачи и проверку данных

**Команда:** Core  
**Зависит от:** I01  
**Результат:** модель задачи проверяет название, дату, приоритет, команду и статус.  
**Готово, когда:** корректные данные принимаются, ошибочные получают понятное сообщение, проверки покрыты тестами.  
**Спринт:** 1

## I03. Добавить локальное хранение задач

**Команда:** Core  
**Зависит от:** I02  
**Результат:** задачи читаются и сохраняются в JSON-файл на компьютере пользователя.  
**Готово, когда:** пустое хранилище создаётся корректно, данные сохраняются между запусками, файл не добавляется в Git.  
**Спринт:** 2

## I04. Реализовать HTTP API задач

**Команда:** Core  
**Зависит от:** I02, I03  
**Результат:** API выдаёт список, создаёт задачу и меняет её статус.  
**Готово, когда:** проверены успешные запросы, ошибки валидации и неизвестные маршруты; сервер слушает только loopback-интерфейс.  
**Спринт:** 2

## I05. Сделать форму и доску задач

**Команда:** Web  
**Зависит от:** I01 и согласованного контракта API  
**Результат:** адаптивная страница с формой задачи и колонками «Бэклог», «В работе», «Готово».  
**Готово, когда:** поля имеют подписи, статусы видны, пустые колонки не выглядят сломанными.  
**Спринт:** 1

## I06. Подключить интерфейс к API

**Команда:** Web  
**Зависит от:** I04, I05  
**Результат:** интерфейс получает задачи с сервера и отправляет создание или смену статуса.  
**Готово, когда:** изменения после перезагрузки остаются сохранёнными, ошибки API показываются пользователю.  
**Спринт:** 3

## I07. Покрыть правила и хранилище модульными тестами

**Команда:** QA + Core  
**Зависит от:** I02, I03  
**Результат:** тесты валидации, сортировки, сохранения и смены статуса.  
**Готово, когда:** команда запускает тесты одной командой и получает воспроизводимый результат.  
**Спринт:** 2

## I08. Провести интеграционную и регрессионную проверку

**Команда:** QA  
**Зависит от:** I04, I06, I07  
**Результат:** сценарий от создания задачи в браузере до сохранения и смены статуса.  
**Готово, когда:** основной сценарий проходит, известные дефекты заведены отдельными карточками.  
**Спринт:** 3

## I09. Настроить CI на локальном runner

**Команда:** Core + QA  
**Зависит от:** I07 и регистрации локального GitFlic Runner  
**Результат:** GitFlic pipeline запускает тесты на компьютере пользователя.  
**Готово, когда:** pipeline показывает успешный job с тестами; runner остаётся локальным и использует метку local-windows.  
**Спринт:** 3

## I10. Подготовить демонстрацию и комплект инструкций

**Команда:** Core + Web + QA  
**Зависит от:** I08, I09  
**Результат:** приложение запускается локально, доска заполнена демонстрационными задачами, Wiki объясняет архитектуру и запуск.  
**Готово, когда:** сценарий защиты можно повторить на одном компьютере без внешней публикации приложения.  
**Спринт:** 4
